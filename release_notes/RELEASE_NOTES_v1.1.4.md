# Wayland-Wheeltani 1.1.4

This release fixes a critical `Permission denied (os error 13)` issue on `/dev/uinput` when running the daemon as a normal, non-root user even after installing the recommended udev rule. It also ensures that permissions are updated instantly without requiring a system reboot.

## Bug Fixes

### 1. `/dev/uinput` permission fix (`OPTIONS+="static_node=uinput"`)

Previously, on some systemd-based Linux distributions, the `uaccess` tag was not properly applied to `/dev/uinput` even though the udev rule was successfully installed. This caused the daemon to fail at startup with:

```text
Error: failed to create /dev/uinput virtual mouse: Permission denied (os error 13)
```

**What went wrong:**
`/dev/uinput` is a static device node created at boot time by the kernel. Under systemd-udevd, the `uaccess` tag (which grants dynamic Access Control List permissions to the active graphical seat session user) is not automatically applied to pre-existing static device nodes unless explicitly declared with a specific static node option.

**The fix:**
The udev rule generated by `wayland-wheeltani --install-udev-rule` (or `--setup`) has been updated to explicitly target the `misc` subsystem and include the static node option:

```udev
KERNEL=="uinput", SUBSYSTEM=="misc", TAG+="uaccess", OPTIONS+="static_node=uinput"
```

This instructs udev to apply `uaccess` ACLs to `/dev/uinput` reliably for your active user session.

### 2. Instant permission application without rebooting

Previously, during installation, the daemon triggered a udev refresh only for the `input` subsystem:

```bash
udevadm trigger --subsystem-match=input --action=change
```

Since `/dev/uinput` belongs to the `misc` subsystem, the permissions on `/dev/uinput` were not refreshed instantly, requiring users to reboot their machine or manually run triggers to get r/w access.

**The fix:**
We now trigger an immediate udev refresh for the `misc` subsystem right after writing the rules:

```bash
udevadm trigger --subsystem-match=misc --action=change
```

Permissions are now applied **instantly** to `/dev/uinput` upon running `--install-udev-rule` or `--setup`. No reboot is needed!

## Upgrade & How to Apply

To benefit from this fix, re-compile the binary and re-install your udev rule:

```bash
# 1. Update/reinstall the binary (forces compilation to version 1.1.4)
cargo install wayland-wheeltani --force

# Or if you are compiling from the checked-out source tree:
cargo install --path crates/middle-scroll-linux --force

# 2. Re-install the udev rules (this will overwrite the old rules file)
sudo "$HOME/.cargo/bin/wayland-wheeltani" --setup --install-udev-rule
```

Once completed, you can check that your user now has read/write permissions on the uinput node without any sudo privileges:

```bash
getfacl /dev/uinput
```

You should see a line granting permissions directly to your username (e.g., `user:lucas:rw-`). You can now run `wayland-wheeltani` seamlessly as a normal user!
